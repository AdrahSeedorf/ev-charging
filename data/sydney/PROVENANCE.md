# Sydney metro dataset — provenance

## Source

`raw/Locations.txt` and `raw/Weights.txt`, preserved byte-for-byte from the
legacy `ev_charging` coursework project: 24 Sydney suburbs, a 24×24 road distance
matrix, per-suburb charger flag and price per kWh.

Nothing in `raw/` is edited. Everything in this directory outside `raw/` is
generated by `tools/build_datasets.py`, which applies the corrections below and
reports each one as it runs.

## Defect 1 — the matrix was one value short

`Weights.txt` contains **575** whitespace-separated numbers. A 24×24 matrix needs
**576**. The `Ryde` row (line 22) has 23 values instead of 24.

This matters more than a missing edge, because the original loader read the file
as a flat token stream:

```cpp
for (int i = 0; i < gSize; i++)
    for (int j = 0; j < gSize; j++) {
        double value;
        infile >> value;          // line breaks are irrelevant to >>
        ...
    }
```

A short row therefore shifts every subsequent value one position earlier, so the
matrix the original program actually loaded was corrupt from `Ryde` onward, and
its shortest-path results for the last three suburbs were wrong. No error was
reported.

The converter reads the file **line per row** — the author's evident intent — and
pads the short row, which localises the damage instead of propagating it.

## Defect 2 — five asymmetric pairs

Read line-per-row, five pairs disagree with their mirror image. All five are
explained by two values placed one column too early plus one missing reverse
edge, and every correction is geographically defensible:

| Raw entry | Problem | Correction |
|---|---|---|
| `Macquarie Pk → Campbelltown = 5.2` | ~50 km apart in reality | dropped |
| `Ryde → Macquarie Pk = 5.2` | correct (~5 km), mirror absent | `Macquarie Pk ↔ Ryde = 5.2` |
| `Fairfield → Leppington = 9.3` | ~13 km in reality | dropped |
| `Liverpool → Fairfield = 9.3` | correct (~9 km), mirror absent | `Liverpool ↔ Fairfield = 9.3` |
| `Campbelltown → Leppington = 14.8` | correct, no reverse | made bidirectional |

After correction the network is undirected, fully connected (24/24 reachable),
and passes `evnet inspect` with no warnings. `tests/test_datasets.cpp` asserts
the Macquarie Park correction specifically, so a regression would fail the build.

Campbelltown is now reached via Leppington rather than via the impossible
Macquarie Park link, which matches the real road geography
(Campbelltown–Leppington–Liverpool).

## Synthetic fields

**Charger counts and power ratings are estimates, not measurements.** The legacy
metro study modelled no congestion whatsoever, so these figures do not exist in
the source data. They are assigned deterministically in
`tools/build_datasets.py`, scaled by how significant each centre is — 8 chargers
at Parramatta, 2 at Manly, 150 kW at the major interchanges and 50 kW elsewhere.

Consequence: **congestion results on the Sydney dataset are illustrative.** The
Hume corridor dataset carries the coursework's own charger counts and is the one
to quote for queueing behaviour. Stage 3 replaces these estimates with open
charger data.

Prices are genuine to the source data. A price of `-1` in `Locations.txt` meant
"no charger" and `0` meant "free of charge"; the schema separates these into a
`has_station` flag and a price, so free charging is no longer indistinguishable
from an absent station.

## Demands

`demands.csv` holds 100 **top-up missions** — `origin == destination` with
`required_kwh > 0`, the round-trip question the legacy study actually asked in its
Tasks 6 and 7. Generated with a fixed seed (`20260817`) so runs are reproducible.
Required amounts span 10–60 kWh, preserving the legacy range.
